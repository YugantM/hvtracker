## Key finding: one dimension dominates

`package_provenance_drift` contributes ±4–5 points and appears as the largest
term in **every** top swing, both directions. The other three runtime
dimensions are small (mcp ≤ +2.0, ext-deps ≥ −3.0, tool-surface ≥ −2.5).
In effect, v2 as currently calibrated is mostly a provenance-drift reweight
with runtime garnish. Before this drives production rank, the drift signal's
false-positive rate needs review — a "mismatch" status is worth −5.0 only if
mismatches are reliably real, not packaging noise.

## Grade-A drops >10 ranks (plan's explicit red flag)

LangGraph −15 · Strands Agents −16 · Open WebUI −14 · ECC −20 ·
Hermes Agent −14 · OpenClaw −16 — **six** A-grade agents, all driven primarily

## Proposed go/no-go criteria (PROPOSED — owner sign-off required)

1. **Churn ceiling:** ≤10% of agents move >10 ranks (currently 19% — fail).
2. **A-grade protection:** no A-grade agent drops >10 ranks without a
   documented per-case cause review (currently 6 unreviewed — fail).
3. **No single-dimension dominance:** no one runtime dimension may account for
   >60% of mean absolute adjustment (drift currently dominates — fail).
4. **Spec first:** `/spec/runtime-trust` (T3.2) published before any cutover
   (not yet published — fail).
5. **Top-10 stability:** turnover ≤2 (currently 2 — pass).

## Verdict: **NO-GO** (as calibrated today)

Four of five proposed criteria fail. Recommended path before re-review:
1. Audit the `package_provenance_drift` "mismatch" evidence on the six A-grade
   droppers — if the signal is right, the drops are *correct* and criterion 2
   becomes documentation, not recalibration.
2. Consider splitting drift's weight (e.g. −5.0 → −2.5 with confidence-scaled
   penalty) so no single dimension dominates.
3. Ship T3.2 (`/spec/runtime-trust`) — publishing the methodology is a
   prerequisite regardless of calibration outcome.
4. Re-run this report after recalibration; both fail-criteria are computed
   mechanically and can be re-checked in minutes.

## Addendum 2026-07-02: same-owner drift fix, re-review

Owner decision on this report: fix the drift detector's false-positive rate
first (option A), then re-run. Investigation of the six A-grade droppers found
the `-5.0` "warning" penalty conflated two different situations: a genuine
different-owner package mismatch (real ambiguity — could be squatting or an
unrelated collision) vs. a **same-owner, different-repo** mismatch (a JS/Python
split, a rename, a monorepo carve-out — not evidence of hijack). Dataset-wide,
**12 of 26 warning-status agents (46%)** were the same-owner pattern.

**Fix shipped:** `detect_package_provenance_drift` now scores a same-owner
mismatch as `unknown` (inconclusive, 0 adjustment) instead of `warning`
(-5.0), while a genuine different-owner mismatch still warns unchanged. See
`fetch_and_build.py` (`detect_package_provenance_drift`) and the regression
tests in `tests/test_helpers.py`.

### Also corrected: the original dominance calculation was wrong

The original §"Key finding: one dimension dominates" was based on eyeballing
the top-swings table, not a computed aggregate. Recomputed properly (mean of
per-dimension **|adjustment|**, not the netted total, which sign-cancellation
distorts): drift was **37%** of the summed mean adjustment before this fix —
the largest single dimension, but never close to the proposed 60% dominance
threshold. Criterion 3 should have read PASS from the start.

### Criteria, before vs. after

| # | Criterion | Before | After | Status |
|---|---|---|---|---|
| 1 | Churn ≤10% moving >10 ranks | 19% | 18% | still **FAIL** |
| 2 | No A-grade drops >10 unreviewed | 6 | **4** | still **FAIL**, improved |
| 3 | No dimension >60% of adjustment | 37% *(mis-graded fail)* | 34% | **PASS** (correction) |
| 4 | Spec published first | not yet | ✅ `/spec/runtime-trust` live | **PASS** |
| 5 | Top-10 turnover ≤2 | 2 | 2 | **PASS** |

LangGraph and ECC — the two clearest false positives — are now correctly
cleared from the A-grade drop list. The remaining four (Strands Agents,
Hermes Agent, OpenClaw, Open WebUI) are **not** detector bugs:

- Strands Agents / Hermes Agent / OpenClaw's PyPI mismatch point to genuinely
  *different* owners — real ambiguity between squatting and an unrelated name
  collision that a URL comparison alone cannot resolve.
- Open WebUI's drop was **never driven by drift** (`unknown` status, 0
  adjustment) — it's `external_dependencies` (-4.0) and `tool_plugin_surface`
  (-1.8). It was mis-attributed in the original top-drops table.

### Verdict: still **NO-GO**, for a narrower reason

Churn (criterion 1) is not primarily a drift problem — it's spread across all
four runtime dimensions, so fixing drift's false positives alone was never
going to clear a 10% churn ceiling. Two real paths forward, owner's call:

1. **Investigate the remaining ambiguous cases manually** (confirm whether
   Strands/Hermes/OpenClaw's mismatched packages ever belonged to the
   project) — resolves criterion 2 but not criterion 1's broader churn.
2. **Revisit whether the 10% churn ceiling is the right bar** for a first-pass
   calibration touching four independent signals at once — a stricter
   per-dimension rollout (e.g., ship MCP + drift as v2 first, hold
   ext-deps/tool-surface for a second pass) might clear the ceiling by
   reducing how many dimensions can move any one agent at once.

## Addendum 2 (2026-07-02): manual investigation of the 3 remaining agents

Owner chose option 1. Queried the live npm/PyPI registry APIs (publish date,
maintainer, author, description) for each configured package rather than
relying on the URL comparison alone.

- **Strands Agents** — `npm_package: strands` was wrong. That package is an
  unrelated JavaScript string-formatting library published in **2016**, years
  before the agent framework existed — not squatting, a pre-existing name
  collision. The project's real npm package is the scoped `@strands-agents/sdk`
  (verified via npm search; its `repository` field points to the correct org).
  **Fixed** — `npm_package` corrected to `@strands-agents/sdk` in `agents.json`.
  Separately surfaced, **not fixed here**: the tracked repo
  `strands-agents/sdk-python` 301-redirects — the project renamed to
  `strands-agents/harness-sdk`. Left as a follow-up since correcting a tracked
  `repo` field has a bigger blast radius (history-snapshot continuity, slug
  stability) than a package-name fix and deserves its own review.
- **Hermes Agent** — `npm_package: hermes-agent` was wrong. No genuine
  official npm package exists (search confirms; the project is Python-only).
  The listed package explicitly self-describes as an **"Unofficial npm bridge
  for Hermes Agent"** by a third party — disclosed, not deceptive, but not
  the project's own package either. **Fixed** — `npm_package` removed. The
  configured `pypi_package: hermes-agent` is genuinely theirs (author "Nous
  Research", matching description) and already correctly resolves to
  `unknown` (no `project_urls` published), not `warning` — left unchanged.
- **OpenClaw** — `pypi_package: openclaw` was wrong. That PyPI package belongs
  to an unrelated commercial tool ("CMDOP", `commandoperator/cmdop-sdk`) that
  happens to share the name. OpenClaw's npm package is already correct and
  verified. **Fixed** — `pypi_package` removed (OpenClaw is npm/JS-focused;
  no verified official PyPI package exists to configure in its place).

All three were the same root cause: `agents.json` had unverified package-name
*guesses*, not evidence of hijacking or squatting of a real official package.
None was a supply-chain risk.

**Conclusion: option A (drift investigation) is exhausted — done, evidenced,

drift issue. Clearing criterion 1 now requires option B: either accept a
higher churn ceiling for a first-pass calibration touching four independent
dimensions at once, or ship a reduced-dimension rollout (e.g., MCP + drift
first, hold ext-deps/tool-surface for a second pass) so fewer signals can
move any one agent simultaneously.
