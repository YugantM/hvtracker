## Post copy (paste into LinkedIn)

A second open-source AI agent just put HVTrust on their README — by their own choice.

Two weeks ago, deepset's **Haystack** (25.5k stars, rank #1 on HVTracker) embedded the badge first.

Today, **AIPass** — a 190-star "persistent agent workspace" — did the same. They're rank #41 with a trust score of 77/100 and an evidence grade of B.

That contrast is the point.

The interesting thing isn't the number on either badge. It's the willingness to put a verifiable, externally-computed number — one that includes things like signed commits, OSSF Scorecard, build provenance, and license clarity — on the front door of your repo, where any visitor can click through and see the working.

Most README badges measure things a project controls: stars, downloads, build status. Those go up. HVTrust includes things a project doesn't fully control: third-party security scores, attestation chains, dependency hygiene. Those can go down — publicly.

Adding it is a tiny act of transparency. It says: I'd rather you see how my project actually scores than have you guess from the star count.

Two projects in, this is what the maintainer flywheel was supposed to look like.

If you maintain an open-source AI agent and want to surface your trust signals the same way: https://hvtracker.net/badges/

## Why this post matters

This is the second data point on a curve. The pitch was always:
*maintainers will adopt verifiable trust signals once it's frictionless*.
Two adopters from very different parts of the ecosystem (an established
RAG framework + a brand-new persistent-agent workspace) is the first
hint that the curve is real.

Don't post this every time someone adopts — wait for milestones (5
adopters, 10 adopters, first maintainer-initiated PR back to a top-20
agent). Otherwise the audience burns out.
