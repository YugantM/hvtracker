## 2. Railway bill fix — verification (2026-07-06)

The fix (#106, deployed 2026-07-05 ~15:30 UTC) runs each refresh render as a
subprocess so the render working set is returned to the OS instead of
ratcheting the uvicorn heap.

Measured via Railway metrics API (web service, MEMORY_USAGE_GB, ~1-min
resolution):

| Window | avg | median | p95 | max |
|---|---|---|---|---|
| Pre-fix (07-03 00:00 → 07-05 15:40 UTC) | **0.660 GB** | 0.834 | 0.953 | 0.964 |
| Post-fix (07-05 15:40 → 07-06 UTC) | **0.228 GB** | 0.218 | 0.274 | 0.742 |

- Pre-fix profile: classic ratchet — climbs to ~0.95 GB and pins there.
- Post-fix profile: flat ~0.2 GB baseline; brief spikes (0.4–0.74 GB) during
  renders that **fully release** afterwards. Hourly averages stay in
  0.17–0.28 GB with no upward trend.
- Estimated memory line item: **$6.60/mo → $2.28/mo (−65%)** at ~$10/GB-mo.
  Memory was ~83% of the web service cost, so this is the dominant saving.

**Verdict: WORKING.** Follow-ups:

- [ ] Remaining cost lever: the account still runs **two Postgres services**
